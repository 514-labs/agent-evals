CLI structure and agent efficiency
an empirical study

300 agent runs · Claude Sonnet 4.6 · 5 CLI variants × 6 tasks × 10 reps · source · workflow

Abstract

We ask whether the shape of a CLI changes how efficiently an AI coding agent can use it. Five CLIs with identical capabilities but different command structures were exercised against six tasks, ten repetitions per cell (n = 300).

For one-off tasks, flat CLIs outperform nested ones by about 2× on tool calls. For multi-task sessions, the ordering reverses: nested CLIs outperform flat ones by about 1.5× because the agent learns the namespace once and reuses it. The crossover is near four related tasks per session.

A fully flat design — every capability as its own top-level verb, which the "agents want flat" heuristic would prescribe — produced the highest error rate. Flat enumeration does not constrain the model's lexical guesses; agents hallucinate verbs that do not exist.

The practical implication is that CLI structure should be chosen to match expected session length, not the identity of the executor.

1. Background

Is flat actually better for agents?

A common design heuristic holds that LLM coding agents prefer flat, fully-enumerable CLIs to nested ones. The argument: agents have no persistent mental model, so every capability should be visible in a single --help response1.

If the heuristic is right, an all-flat variant should dominate every metric against any nested alternative. It does not. The effect of structure on efficiency reverses with workload.

2. Methods

Design

Five Python wrapper scripts2 expose the same 40-capability surface — mirroring the real Moose CLI3 — under five different structures. Six task prompts were issued: five single tasks and one combined session running the five in sequence. Ten repetitions per cell; n = 300.

variantshapeexample
Deep3-level namespacemoose infra logs --filter error
Shallowmixed (mirrors real Moose)moose logs --filter error
Positionalflat, domain as positionalmoose logs error
Flagflat, domain as flagmoose logs --filter error
Atomicone flat verb per capabilitymoose search-logs error

Harness

Each run executes inside a fresh minimal Ubuntu 24.04 container with no pre-existing ~/.claude/ state4. The agent is invoked via claude -p --bare, which disables hooks, plugins, auto-memory, keychain OAuth, and CLAUDE.md auto-discovery. Authentication is via ANTHROPIC_API_KEY. Tool access is limited to Bash.

The full stream-json stream is captured per run. Per-cell statistics are mean ± standard error over n=10 reps5.

Amortization

The ratio of combined-task cost to single-task cost measures how much structural knowledge the agent carries across tasks. Near 1 indicates perfect amortization; near 5 indicates none.

Deep's ratio is 1.6×. Positional's is 3.5×.

Under a linear model — single-task cost paid once, marginal cost (combined − single) / 4 thereafter — the cumulative curves cross near N ≈ 4 tasks per session (Figure 1).

4. Discussion

Structure is a scaffold, not a human concession

The conventional framing — structure helps humans, flat helps agents — does not fit the data. Both benefit from the right structure for the workload. The distinguishing property is session length, not executor identity.

On a single task, structural exploration cost exceeds its benefit; nothing can be reused. Flat layouts win6.

On a multi-task session, the inverse holds. After one help read, a namespaced CLI routes further tasks without re-consulting help. Trace evidence of this transfer appears in §5.2.

Atomic as a cautionary design

Atomic exists because the heuristic under test recommends it. It loses every metric. The trace-level reason: flat kebab enumeration gives agents unlimited lexical surface to guess plausible-sounding verbs. Nothing in the surface rejects the guess.

5. Trace evidence

Every claim has a trace receipt7. Five characteristic failure modes follow, one per variant.

5.1 Atomic — verb hallucination

Task b, rep 5. The agent's first command chains three invented verbs before reading help:

moose logs --filter error 2>/dev/null \
  || moose logs | grep -i error 2>/dev/null \
  || moose log --filter error 2>/dev/null
→ error: unknown command 'logs'. Did you mean `moose search-logs`?

moose search-logs --help
→ Usage: moose search-logs [QUERY] [-t|--tail] [-f|--filter <STRING>]

moose search-logs error
→ [moose-runtime] 2026-04-23T12:00:00Z INFO server started on :4000

The word "logs" is absent from Atomic's lexicon, but the English phrasing cues a verb containing it. Flat enumeration does not constrain the cue.

5.2 Deep — namespace transfer

Combined session, rep 1. One help read, then five clean commands across three namespaces:

20:37:04  init events --template python-ckh           → error:unknown
20:37:05  --help                                      → help:top
20:37:08  project init events --template python-ckh   → matched:init
20:37:10  data seed --source ...                      → matched:seed
20:37:12  infra ps                                    → matched:ps
20:37:14  data ls                                     → matched:ls
20:37:17  infra logs --filter error                   → matched:logs

The agent learns the namespace partition once and applies it to four subsequent tasks without re-consulting help. Amortization visible at the command level.

5.3 Shallow — subcommand hallucination

Combined, rep 1. Task phrasing ("seed from a remote DB") cues a non-existent seed remote:

20:37:46  seed remote --source-connection-string ...  → error:unknown
20:37:48  seed --help                                 → help:verb:seed
20:37:53  seed clickhouse --clickhouse-url ...        → matched:seed

The per-verb help tree recovers the invocation cheaply.

5.4 Positional — worse recovery, identical in 10/10 reps

Positional inherits Shallow's miss but has no per-verb help to drill into:

20:38:29  seed remote --url ...                       → error:unknown
20:38:30  seed --help                                 → error:unknown
20:38:32  --help                                      → help:top

Two errors, one extra help read, every run.

5.5 Flag — recovery without help

Flag's explicit-flag convention makes errors self-describing:

20:39:16  seed remote --url ...                       → error:incomplete
20:39:18  seed remote --source clickhouse --url ...   → matched:seed

One flag added; no help read.

6. Limitations

  • Single model. All measurements are Sonnet-4.6-specific. A Codex / GPT-5 rerun is queued.
  • Simulated tool. Wrappers produce canned output, isolating CLI structure as the variable but removing state-dependence.
  • Shallow priors. Shallow matches real Moose, which the model plausibly encountered in training. Shallow numbers are biased favourably; Shallow did not, however, win any metric.
  • Task coupling. The combined session is weakly coupled. Tightly coupled sequences may amplify structural advantages.
  • Linear amortization. The break-even projection assumes constant marginal cost beyond the first task. Cannot be verified with n=10 at N=5.
