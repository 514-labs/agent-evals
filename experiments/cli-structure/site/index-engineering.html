Run these to audit your CLI

Five prompts you can paste into Claude Code in a clone of your CLI's repo. Each targets one failure mode from our trace data.

audit-1 · verb hallucination
You have the ACME CLI on PATH. Without reading any docs or source code, describe ten tasks you'd plausibly want to do with it and the command you would try first for each. Then run each and count how many failed with "unknown command" on the first attempt. Report: first-try success rate, and the verbs you expected but don't exist.
claude -p "$(cat audit-1.md)" --allowedTools "Bash"
audit-2 · help traversal cost
You have the ACME CLI on PATH. For the task "list the tables in the running project," measure: how many --help calls you made before running a non-help command, whether any were unnecessary (you could have guessed), and how many total commands you ran. Report the numbers and your first --help call path.
claude -p "$(cat audit-2.md)" --allowedTools "Bash"
audit-3 · multi-task amortization
You have the ACME CLI on PATH. Complete these five tasks in order: [TASK LIST]. After finishing, report: how many --help calls you made total, whether any were redundant (you re-read help for a thing you'd already figured out), and the cost ratio of task 5 compared to task 1 in tool calls.
claude -p "$(cat audit-3.md)" --allowedTools "Bash"
audit-4 · error recovery cost
You have the ACME CLI on PATH. Deliberately run three commands that look plausible but you suspect don't exist. For each: report whether the error message told you how to fix it, whether you had to read help to recover, and how many extra tool calls the recovery took.
claude -p "$(cat audit-4.md)" --allowedTools "Bash"
audit-5 · top-level help coverage
Run the ACME CLI's top-level --help. Without running anything else, list: (a) what you believe are the five most common tasks, (b) for each, the command you'd try first, (c) which of those you could compose from the help output alone vs which required guessing. Report any where the help text left you guessing.
claude -p "$(cat audit-5.md)" --allowedTools "Bash"

The patterns, with trace receipts

Five characteristic failure modes pulled from the 300-run dataset. Expand each for the raw trace.

Pattern 1 · Atomic → verb hallucination

Three invented verbs tried before reading help. Replicated in 9/10 Atomic/b reps.

source · runs/atomic/b/rep5/moose.log · 3 err + 1 help

→ error: unknown command 'logs'. Did you mean `moose search-logs`?

moose search-logs --help

Task phrasing cues a non-existent subcommand; per-verb help recovers cheaply.

Inherits Shallow's seed remote miss but has no per-verb help. Identical sequence in 10/10 reps.

What to do in your CLI

  • Never ship all-flat-kebab. It reliably produces 3 errors per 5-task session. The flat lexical space encourages verb hallucination.
  • If usage is one-off (health checks, simple queries): flat with positional disambiguation (tool resource action) is cheapest.
  • If usage is orchestration (multi-step workflows): nest the full surface, then surface 5–7 common verbs as top-level aliases. Think git commit vs git config --get.
  • Always provide per-verb help (tool verb --help). Positional and Atomic lose their biggest recovery path without it.
  • Make errors self-describing when you can. Flag's error:incomplete pattern lets agents recover without reading help — one flag fix, done.
