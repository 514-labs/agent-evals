---
title: "Designing Cross-Domain Scenarios"
description: "Combine assumptions from multiple business domains in a single evaluation scenario."
---

For advanced evals, you can combine assumptions from multiple domains (for example, e-commerce plus usage-based infrastructure).

## When to combine domains

Cross-domain scenarios test whether the agent can reason across business contexts. They are appropriate when the real-world task naturally spans multiple domains, not when complexity is the goal in itself.

## Guidelines

- Document domain boundaries explicitly in the prompt. The agent should understand which data belongs to which domain.
- Keep ownership of each metric clear. If revenue comes from the e-commerce domain and cost comes from the infra domain, say so.
- Avoid ambiguous source-of-truth definitions. When two domains define the same concept differently (e.g., "active user"), pick one and document the choice.
