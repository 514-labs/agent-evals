---
title: "Adding Persona Prompts"
description: "Write baseline and informed prompts that test how domain knowledge in the prompt affects agent performance."
---

Each scenario includes two prompts, one per persona. Both prompts ask for the same outcome and are scored against the same assertions. The persona changes how much context the user provides, not what success looks like.

## The two personas

**Baseline** prompts use plain language with no tool names, no schema details, and no implementation hints. They test what the agent can figure out on its own.

**Informed** prompts name specific tools, set explicit targets, and provide technical constraints. They test whether giving the agent domain knowledge changes the outcome.

## Writing a baseline prompt

Write it the way a non-technical stakeholder would describe the problem. Focus on the desired outcome, not the method.

```markdown title="prompts/baseline.md"
I have a bunch of CSV files that need to go into ClickHouse.
Some of them have messy data -- weird dates, missing values.
Can you get it all loaded into a clean table?
```

Avoid leaking implementation details. If the baseline prompt mentions specific column names, table schemas, or tool commands, it is doing the informed prompt's job.

## Writing an informed prompt

Write it the way an experienced data engineer would hand off a task. Be specific about tools, schemas, and edge cases.

```markdown title="prompts/informed.md"
Ingest five CSV files from /data/csv/ into a single ClickHouse
table `analytics.events`. Handle DD/MM/YYYY dates, mixed null
representations (N/A, null, empty), duplicate header rows
mid-file, and trailing delimiters. Target schema: event_id
String, event_ts DateTime, user_id String, event_type String,
value Float64 (nullable values should be 0).
```

## What the comparison reveals

When an agent passes with the informed prompt but fails with the baseline prompt, the benchmark surfaces a gap: the agent needed domain knowledge it could not infer. When both prompts produce the same result, the agent is either fully capable or fully stuck regardless of guidance.

This distinction is central to the benchmark. The same assertions, applied to both personas, measure the delta between "agent with help" and "agent without help."

## Guidelines

- Keep both prompts aligned to the same acceptance criteria. Do not add requirements in the informed prompt that the baseline prompt omits entirely.
- The baseline prompt should be solvable. If no agent can pass without detailed guidance, the scenario may be testing prompt quality rather than agent capability.
- Avoid ambiguity in the informed prompt. If the informed prompt is vague about the target schema, assertion failures will be hard to interpret.
