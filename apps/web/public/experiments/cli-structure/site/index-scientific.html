Abstract

We ask whether the shape of a CLI changes how efficiently an AI coding agent can use it. Seven CLIs with identical capabilities but different command structures were exercised against six tasks, ten repetitions per cell (n = 420).

A git-style hybrid (Surfaced: nested underneath, with seven common verbs surfaced as top-level aliases) wins both regimes. On single tasks it ties the flat winner (1.76 ± 0.12 tool calls vs Positional's 1.52 ± 0.27). On the five-task combined session it minimises tool calls (6.10 ± 0.10), help reads (zero) and errors (zero) simultaneously — beating the previous best (Deep at 8.00) by 24%.

A fully flat design — every capability as its own top-level verb, which the "agents want flat" heuristic would prescribe — again produced the highest error rate. Flat enumeration does not constrain the model's lexical guesses; agents hallucinate verbs that do not exist. A help-text-only intervention (Signposted: Deep with canonical examples in --help) yields a modest improvement over Deep but is dominated by Surfaced.

The practical implication is that the git-style hybrid empirically dominates both single-operation and orchestration regimes. The previously useful "match shape to session length" framing collapses once a hybrid is included in the comparison set.

§ · §

§ 1Background

Is flat actually better for agents?

A common design heuristic holds that LLM coding agents prefer flat, fully-enumerable CLIs to nested ones. The argument: agents have no persistent mental model, so every capability should be visible in a single --help response1.

If the heuristic is right, an all-flat variant should dominate every metric against any nested alternative. It does not. With the original five variants the effect of structure reversed with workload. A subsequent follow-up (§2, note 8) probed two further designs — a git-style hybrid and a help-text-only intervention — and showed that the hybrid uniformly dominates both regimes.

§ 2Methods

Design

Seven Python wrapper scripts2 expose the same 40-capability surface — mirroring the real Moose CLI3 — under seven different structures. The original five (Deep, Shallow, Positional, Flag, Atomic) were probed in workflow run 24910674972; two design probes (Signposted, Surfaced) were added on the same harness in run 249236116818. Six task prompts were issued: five single tasks and one combined session running the five in sequence. Ten repetitions per cell; n = 420.

Harness

Each run executes inside a fresh minimal Ubuntu 24.04 container with no pre-existing ~/.claude/ state4. The agent is invoked via claude -p --bare, which disables hooks, plugins, auto-memory, keychain OAuth, and CLAUDE.md auto-discovery. Authentication is via ANTHROPIC_API_KEY. Tool access is limited to Bash.

The full stream-json stream is captured per run. Per-cell statistics are mean ± standard error over n=10 reps5.

§ 3Results

Single tasks: flat variants win, Surfaced ties

On single tasks, Positional required the fewest tool calls, fewest help reads, and zero errors. Amortization

The ratio of combined-task cost to single-task cost separates how the variants carry structure across tasks. Deep and Signposted amortise tightly (1.64× and 1.73×) — the agent learns the namespace once and reuses it. Surfaced does not amortise as tightly (2.37×) only because it has no namespace to learn — the surfaced flat aliases are used throughout — yet its absolute cost remains lowest of any variant on the combined task.

Surfaced is cheapest in absolute terms in both regimes. Deep amortises tightest. Positional pays full price every time (3.52×).

Under a linear model the cumulative-cost projections diverge: Surfaced lies below every other curve at every N (Figure 1). The earlier "N ≈ 4 crossover" applied within the original five variants only.

§ 4Discussion

The hybrid resolves both regimes

The conventional framing — structure helps humans, flat helps agents — does not fit the data. Neither does the refined "match shape to session length" framing once a hybrid is included. Surfaced's design — nested underneath, with the seven most-common verbs (init, dev, build, logs, ps, ls, seed) surfaced as top-level aliases that dispatch to their canonical namespaced form — is git-style. The agent never needs to choose between flat and nested; the surface accepts both.

In the combined-task trace (§5.1), the agent issued five commands using only the flat alias forms — no help reads, no errors. Signposted (Deep with canonical paths shown in --help) is a useful but smaller win: it does not change the command surface, only the help text, and agents that skip help cannot benefit.

Atomic as a cautionary design

Atomic exists because the heuristic under test recommends it. It loses every metric. The trace-level reason: flat kebab enumeration gives agents unlimited lexical surface to guess plausible-sounding verbs. Nothing in the surface rejects the guess. Surfaced inherits the agent-friendly flat shortcut without the unbounded surface — its seven aliases are all the agent ever needs, and the rest of the namespace is still reachable.

§ 5Trace evidence

Every claim has a trace receipt7. Seven characteristic patterns follow, one per variant. The first two — Surfaced and Signposted — show the winning patterns from the follow-up run.

5.1 Surfaced — the winning pattern

Combined session, rep 1. Five commands, zero errors, zero help reads — the agent uses the surfaced top-level aliases throughout:

05:30:19  init events --template python-ckh                → matched:init
05:30:22  seed clickhouse --source-connection-string ...   → matched:seed
05:30:27  ps                                               → matched:ps
05:30:29  ls --tables                                      → matched:ls
05:30:31  logs --filter error                              → matched:logs

The agent's first instinct on every task is the flat verb. Surfaced accepts it. There is no exploration phase, no namespace-learning phase, no help round-trip. This pattern is what produces the 6.10 tool-calls / zero-error / zero-help-read combined-task figures.

5.2 Signposted — recovery via canonical examples in --help

Combined session, rep 1. The agent guesses the flat form, fails, reads --help (which shows canonical example invocations), then routes all tasks correctly using the namespaced form:

05:29:40  init events --template python-ckh                → error:unknown
05:29:42  --help                                           → help:top
05:29:44  project init events python-ckh                   → matched:init
05:29:46  data seed clickhouse --clickhouse-url ...        → matched:seed
05:29:49  infra ps                                         → matched:ps
05:29:51  data ls --type Table                             → matched:ls
05:29:54  infra logs --filter error                        → matched:logs

Compared to plain Deep, the per-verb correction is faster: --help shows moose data ls --type Table directly, so the agent picks the right invocation immediately rather than re-reading data --help.

5.3 Atomic — verb hallucination

Task b, rep 5. The agent's first command chains three invented verbs before reading help:

moose logs --filter error 2>/dev/null \
  || moose logs | grep -i error 2>/dev/null \
  || moose log --filter error 2>/dev/null
→ error: unknown command 'logs'. Did you mean `moose search-logs`?

moose search-logs --help
→ Usage: moose search-logs [QUERY] [-t|--tail] [-f|--filter <STRING>]

moose search-logs error
→ [moose-runtime] 2026-04-23T12:00:00Z INFO server started on :4000

The word "logs" is absent from Atomic's lexicon, but the English phrasing cues a verb containing it. Flat enumeration does not constrain the cue.

5.4 Deep — namespace transfer

Combined session, rep 1. One help read, then five clean commands across three namespaces:

20:37:04  init events --template python-ckh           → error:unknown
20:37:05  --help                                      → help:top
20:37:08  project init events --template python-ckh   → matched:init
20:37:10  data seed --source ...                      → matched:seed
20:37:12  infra ps                                    → matched:ps
20:37:14  data ls                                     → matched:ls
20:37:17  infra logs --filter error                   → matched:logs

The agent learns the namespace partition once and applies it to four subsequent tasks without re-consulting help. Amortization visible at the command level.

5.5 Shallow — subcommand hallucination

Combined, rep 1. Task phrasing ("seed from a remote DB") cues a non-existent seed remote:

20:37:46  seed remote --source-connection-string ...  → error:unknown
20:37:48  seed --help                                 → help:verb:seed
20:37:53  seed clickhouse --clickhouse-url ...        → matched:seed

The per-verb help tree recovers the invocation cheaply.

5.6 Positional — worse recovery, identical in 10/10 reps

Positional inherits Shallow's miss but has no per-verb help to drill into:

20:38:29  seed remote --url ...                       → error:unknown
20:38:30  seed --help                                 → error:unknown
20:38:32  --help                                      → help:top

Two errors, one extra help read, every run.

5.7 Flag — recovery without help

Flag's explicit-flag convention makes errors self-describing:

20:39:16  seed remote --url ...                       → error:incomplete
20:39:18  seed remote --source clickhouse --url ...   → matched:seed

One flag added; no help read.

§ 6Limitations

  • Single model. All measurements are Sonnet-4.6-specific. A Codex / GPT-5 rerun is queued.
  • Simulated tool. Wrappers produce canned output, isolating CLI structure as the variable but removing state-dependence.
  • Shallow priors. Shallow matches real Moose, which the model plausibly encountered in training. Shallow numbers are biased favourably; Shallow did not, however, win any metric.
  • Task coupling. The combined session is weakly coupled. Tightly coupled sequences may amplify structural advantages.
  • Linear amortization. The break-even projection assumes constant marginal cost beyond the first task. Cannot be verified with n=10 at N=5.
  • Surfaced and Signposted as design probes. Both were added in a follow-up workflow run (24923611681) on the same harness, container image, runner code, and prompts as the original five variants. The directional finding (Surfaced wins both regimes) is robust; the exact figures carry the same n=10 uncertainty as the rest.

App. CCLI schemas

Top-level --help output for each variant wrapper. The wrappers also accept per-namespace and per-verb help drill-downs (where applicable); only the top level is reproduced here for compactness. Source: variants/.

Deep — 3-level namespace

Every operation lives under one of six namespaces. Top-level --help only reveals the namespaces; commands and flags require drill-down.

Moose CLI (simulated DEEP variant) - 3-level namespacing

Usage: moose <namespace> <command> [ARGS] [OPTIONS]

Namespaces:
  project       Project lifecycle: init, build, check, plan, migrate, harness, components, templates
  infra         Infrastructure runtime: dev, prod, clean, logs, ps, metrics
  data          Data operations: peek, query, ls, seed, truncate, db pull
  runtime       Workflow runtime: run, resume, list, history, cancel, pause, unpause, status
  integration   External integrations: kafka, refresh, add components, mcp
  meta          Codegen and meta: generate, docs, feedback

Run `moose <namespace> --help` to see commands within that namespace.
Run `moose <namespace> <command> --help` for per-command flags.
