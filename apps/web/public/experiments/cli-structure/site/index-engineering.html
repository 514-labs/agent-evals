Three hundred Claude sessions across five CLI shapes, same capability surface. Flat layouts win single tasks; nested layouts win multi-task sessions. The crossover sits near four related commands per session. This page is the working engineer's summary — numbers, prompts to audit your own CLI, and trace receipts for every claim.

§06 · AGENT AUDIT

Five prompts to audit your CLI.

Paste into Claude Code (or your agent of choice) in a clone of your CLI's repo. Each targets one failure mode surfaced in the traces below.

AUDIT 01Verb hallucination
You have the ACME CLI on PATH. Without reading any docs or source, describe ten tasks you'd plausibly want to do with it and the command you would try first for each. Then run each and count how many failed with "unknown command" on the first attempt. Report the first-try success rate and the verbs you expected but don't exist.
claude -p "$(cat audit-01.md)" --allowedTools "Bash"
AUDIT 02Help traversal cost
For the task "list the tables in the running project" with the ACME CLI: measure how many --help calls you made before a non-help command, whether any were unnecessary, and how many total commands you ran. Report the numbers and the path of your first --help call.
claude -p "$(cat audit-02.md)" --allowedTools "Bash"
AUDIT 03Multi-task amortization
Complete these five tasks in order with the ACME CLI: [TASK LIST]. Report: total --help calls; any redundant ones (re-read help for something you'd already learned); the tool-call count of task 5 vs task 1.
claude -p "$(cat audit-03.md)" --allowedTools "Bash"
AUDIT 04Error recovery cost
Run three commands against the ACME CLI that look plausible but you suspect don't exist. For each: did the error message tell you how to fix it? Did you have to read help to recover? How many extra tool calls did recovery take?
claude -p "$(cat audit-04.md)" --allowedTools "Bash"
AUDIT 05Top-level help coverage
Run the ACME CLI's top-level --help. Without running anything else, list: (a) what you believe are the five most common tasks, (b) for each, the command you'd try first, (c) which you could compose from help alone vs. which required guessing.
claude -p "$(cat audit-05.md)" --allowedTools "Bash"
§07 · TRACE EVIDENCE

Five failure modes, one per variant.

Each claim above traces to a specific run. Expand for the raw moose.log extract.

Pattern 01 · Atomic → verb hallucination runs/atomic/b/rep5 · 3 err + 1 help · 9/10 reps 
# agent attempt
moose logs --filter error 2>/dev/null \
  || moose logs | grep -i error 2>/dev/null \
  || moose log --filter error 2>/dev/null
→ error: unknown command 'logs'. Did you mean `moose search-logs`?

moose search-logs --help
→ Usage: moose search-logs [QUERY] [-t|--tail] [-f|--filter <STRING>]

moose search-logs error
→ [moose-runtime] server started on :4000

Three invented verbs chained with || before the agent concedes and reads help. Flat kebab enumeration leaves unlimited lexical surface to guess; the English phrase "search the logs" cues a verb containing logs, which doesn't exist here. Nothing rejects the cue until the error fires.

Pattern 02 · Deep → namespace transfer (winning) runs/deep/combined/rep1 · 1 err + 1 help + 5 hits 
20:37:04  init events --template python-ckh          → error:unknown
20:37:05  --help                                     → help:top
20:37:08  project init events --template python-ckh  → matched:init
20:37:10  data seed --source ...                     → matched:seed
20:37:12  infra ps                                   → matched:ps
20:37:14  data ls                                    → matched:ls
20:37:17  infra logs --filter error                  → matched:logs

One help read. Agent learns the namespace partition (project/, data/, infra/) and routes four further tasks without re-consulting help. Amortization visible at the command level.

Pattern 03 · Shallow → subcommand hallucination runs/shallow/combined/rep1 
20:37:46  seed remote --source-connection-string ...  → error:unknown
20:37:48  seed --help                                 → help:verb:seed
20:37:53  seed clickhouse --clickhouse-url ...        → matched:seed

Task phrasing ("seed from a remote DB") cues the non-existent seed remote. Per-verb help drill recovers cheaply.

Pattern 04 · Positional → same hallucination, worse recovery runs/positional/combined/rep1 · identical in 10/10 reps 
20:38:29  seed remote --url ...     → error:unknown
20:38:30  seed --help               → error:unknown
20:38:32  --help                    → help:top
20:38:37  seed clickhouse --clickhouse-url ...  → matched:seed

Inherits Shallow's miss but has no per-verb help to drill into — seed --help itself errors. Agent falls back to top-level help dump.

Pattern 05 · Flag → recovery without help runs/flag/combined/rep1 
20:39:16  seed remote --url ...                       → error:incomplete
20:39:18  seed remote --source clickhouse --url ...   → matched:seed

Self-describing error names the missing flag. One incremental flag fixes it. No help read.

§08 · RULES OF THUMB

What to do in your CLI.

  • // DON'T · Ship all-flat-kebabIt reliably produces 3 errors per 5-task session. The flat lexical space encourages verb hallucination.
  • // DO · Single-op tools → flat + positionaltool resource action disambiguates in one step; no help read needed.
  • // DO · Orchestration tools → nested + surfaced common verbsGit-style: nest the full surface, then surface the 5–7 most common verbs as top-level aliases.
  • // DO · Always provide per-verb helpPositional and Atomic lose their biggest recovery path without tool verb --help.
  • // DO · Make errors self-describing when you canFlag's error:incomplete pattern lets the agent recover without reading help — one flag fix, done.
