A report on designing tools for AI agents

A CLI
for Humans Agents.

Four hundred and twenty agent sessions across seven CLI shapes. The shape the data picked is the one git arrived at three decades ago — nested underneath, with the common verbs surfaced flat at the top.

Bad CLI  — what we ship today
$ moose workflow run order-pipeline --input='{…}' $ moose generate hash-token --json $ moose seed clickhouse --clickhouse-url 'clickhouse://…'

Real moose --help today. The agent has to drill through a subcommand tree (workflow, generate, seed) before it can do anything. Same pattern as aws, kubectl, terraform. Note: moose already surfaces logs, ps, ls at the top level — the bad cases are the ones still buried.

Good CLI  — what nobody ships yet
$ moose run order-pipeline $ moose seed 'clickhouse://…'

The same operations, surfaced as top-level aliases over the existing nested surface. None of these exist in moose yet. None exist in aws, kubectl, terraform either. The data says shipping them cuts multi-task agent cost by 24%.

I
The hunch

Everyone said agents want flat CLIs.

The argument was simple. Agents have no mental model, so they can't navigate hierarchy. Show them every command in one place. Dump the whole surface flat. That's what a machine wants.

We believed it. We also doubted it. So we built seven versions of the same command-line tool — from deeply nested to fully flat, with two hybrids in between — and paid four hundred and twenty Claude sessions to try them.

Six tasks. Ten repetitions each. Fresh containers, no configuration leakage. We measured tool calls, help reads, errors, cost — and preserved every trace.

II
What we saw

One shape won everything.

On single tasks the flat shapes won, mostly as predicted. On sessions of five related tasks, the ranking reversed for the original five — until we tested the git-style hybrid. Surfaced won both regimes. Five commands. Zero errors. Zero help reads. The agent never had to choose between flat and nested because the surface accepted both.

III
What to build

Build the shape git arrived at.

Nest the full surface. Then surface the five-to-seven most-common verbs at the top level as aliases that dispatch to their canonical namespaced form. This is what Surfaced does, and it wins both regimes empirically.

If you can't surface aliases — say you only control the help text, not the command surface — signpost. Show fully-formed canonical example invocations in your top-level --help. That alone cut combined-task tool calls from 8.0 to 7.1 in our test.

And if you're tempted by the maximalist flat design where every capability is its own kebab-case verb at the top level — don't. It triples the error rate because it gives the agent unlimited lexical surface on which to guess.

Question answered. The shape git arrived at thirty years ago — nested underneath, five-to-seven common verbs surfaced at the top level — does dominate both regimes. The data confirms it: 6.10 tools, zero errors, zero help reads, the cheapest variant in every regime tested.

Design recommendation

Nest the surface.
Surface the shortcuts.

Confirmed, n = 420. The git-style hybrid wins single tasks and multi-task sessions outright — fewest tool calls, zero errors, zero help reads. Never ship one-flat-verb-per-capability. The agent will invent verbs you haven't written.
